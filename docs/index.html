Agentic code generation

Ralph

A single CLI that works two ways: connect to the managed Ralphy backend (no API key needed), or bring your own key and call any LLM provider directly.

Download How it works

Two modes, one binary

Ralph ships as a single binary. How it connects to the AI is controlled by one flag.

Managed

Default — Ralphy backend

Ralph connects to the Ralphy server at ralphy.vellur.in. The AI runs on our infrastructure — no LLM API key required. Sign up for a RALPH_API_KEY and start coding.

$ ralph "fix the failing tests"
BYOK

--byok — Bring Your Own Key

Ralph calls the LLM provider directly from your machine using your own API key. Supports DeepSeek (default) and Sarvam. You pay the provider directly — no middleman.

$ ralph --byok "fix the failing tests"

How the agentic loop works

In both modes, Ralph runs the same four-phase loop. It doesn't guess — it explores your codebase first, then acts.

Phase 1

Explore

Searches the codebase using symbol lookup, regex search, and file outlines to locate relevant code.

Phase 2

Understand

Reads the minimum necessary — the target function, its tests, and immediate callers.

Phase 3

Implement

Applies changes atomically. Multi-location edits happen in a single call to avoid partial states.

Phase 4

Verify

Runs tests after every change. Will not declare done until tests pass.


🧠 Adaptive reasoning

Automatically switches to extended thinking after repeated edit failures or test failures.

💾 Session persistence

Resume where you left off. Context, edits, and history carry across tasks in the same session.

📸 Checkpoints

Snapshot file state and conversation history before destructive operations. Revert any time.

🔍 Rich tool set

File outlines, regex search, glob, symbol index, git diff, and more — all available to the agent.

🎯 Context-aware nudges

Detects when the agent is stuck in a read loop or editing without testing and course-corrects.

🌐 Web search

Optionally connects to Brave Search or SerpAPI for up-to-date knowledge during tasks.

Option A — Homebrew (recommended)

bash

bash
ralph --help

Setup

Choose a mode and set the corresponding environment variable, then point Ralph at your project.

Managed mode (default) — Ralphy backend

Sign up at ralphy.vellur.in/apply to get your RALPH_API_KEY. No LLM provider account needed.

bash — ~/.zshrc or ~/.bashrc
export RALPH_API_KEY="rph-..."
powershell
[Environment]::SetEnvironmentVariable("RALPH_API_KEY", "rph-...", "User")

BYOK mode — Bring Your Own Key

Get a DeepSeek API key from platform.deepseek.com and pass --byok when running.

bash — ~/.zshrc or ~/.bashrc
export DEEPSEEK_API_KEY="sk-..."
powershell
[Environment]::SetEnvironmentVariable("DEEPSEEK_API_KEY", "sk-...", "User")

For Sarvam AI: set SARVAM_API_KEY and add --sarvam alongside --byok.


Usage

Point Ralph at your project and give it a task.

bash — managed mode (default)
# Interactive mode — connects to Ralphy backend
cd /path/to/your/project
ralph

# Single-shot task
ralph "add error handling to the database module"

# Use the pro model
ralph --pro "refactor the auth module"

# Resume the last session
ralph --resume
bash — BYOK mode
# Call DeepSeek directly with your own key
ralph --byok "write unit tests for the auth module"

# Use Sarvam instead of DeepSeek
ralph --byok --sarvam "explain this codebase"

# Point at a custom Ralphy server
ralph --server https://my.ralphy.server "fix the failing tests"
bash — optional: web search (both modes)
# Add one of these to enable web search during tasks
export BRAVE_API_KEY="BSA..."      # Brave Search (preferred)
export SERP_API_KEY="..."          # SerpAPI (fallback)
